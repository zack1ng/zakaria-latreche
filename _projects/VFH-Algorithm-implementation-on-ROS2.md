What is VFH ?
VFH or Vector Field Histogram is an algorithm used as \***local planners** for object avoidance, implemented with autonomous robots, it relays on a ***grid*** that acts as a ***world model*** generated by a two dimensional histogram and updated continuously. to calculate the proper velocities that we need to feed our system, VFH uses two stage data reduction process, in the first stage the histogram is reduced to a ***polar histogram*** that is concentred around the robot momentary location, each sector is an equivalent of a range of angles in the polar histogram, contains a value that represents the obstacle density in the direction of the robot. This algorithm was published in 1991 by Johann Borenstein and Yoran Koren both professors at University of Michigan. it is the successor of the VFF method that was developed from a group with in the same university as the author's of VFH \[1].

# VFH Evolution:

VFH passed through multiple stages of development after its first publication in 1991,

* in 1998 the same author "Johann Borebstein" proposed what is well known as VFH+ which proposed a more reliable solution for sensor noise, latency and low sampling rate, by using hysteresis to caught the slipping values\[2].
* VFH Star: in 2000, Ulrich and Borenstein proposed "VFH star", which is an enhanced version of VFH and VFH+ that uses an additional search and verification algorithm to validate the goal \[3].
these are just some of the proposed enhancements of VFH algorithm, there is many research papers that proposed the usage of VFH for different types of autonomous robots like UAVs \[4].

# Implementation

This tutorial is for the seek of understanding of how robots moves and interact with their environment by using raw data coming from sensors. to implement the VFH algorithm we will use ROS2 as development environment and GZ fortress as a physics simulation environment. from the previous mentioned research papers \[2] \[3], the source of data is coming from an ultrasound sensors. here in our case we will use a 2D LiDAR  \[4] which is a laser based sensor that emits light and measure the time it took to bounce back to define distance. All the data coming from our actuators and sensors is generated by our physics simulation model GZ, then we bridge the raw data to ROS2.

1. LiDAR Parametrization:
Our configuration is set to measure a max distance of 10.0m and a total field of view (FOV) of 160° with an angle min of -80° and an angle max set to +80°. every LiDAR sweep between a range min and max with a specific angle between beams and it is called angle increment, for facilitating the calculations we set angle increment = sector size = 5°. the total number of samples is set to 32 which means that we have a 2D histogram that measures the frequency of 32 sectors.
the whole array of data coming from our LiDAR needs to be treated, all non and inf values needs to be presented in our calculation since we choose increment angle = sector size all the distances measured can't be dropped. we will see later how we are going to handle nan and inf values.
2. Robot:
Oppressor mk2 is the robot of our choice to simulate the algorithm, it is equipped by an RGB Camera and a LiDAR. the control of the wheels is handled with ros2\_control in differential drive.
3. Algorithm:
The main goal of the development of this algorithm on oppressor mk2 is to enhance the line follower project \[5] by presenting a solution for the objects that comes across our robot path.
* Sensor Reading: First we need to create a subscribe to read from our bridged topic called "/scan" of message type "sensor\_msgs/msg/LaserScan".
* Nan and inf values filtration:  all the distances stored inside ranges needs to be filtered for any distance that holds a nan or inf, we  set its distance to 0 and magnitude we don't need to calculate it, we set it directly to 0.
* Distances processing:  if we read any value other than "nan" and "inf" we proceed to calculate it is equivalent angle (in radian), sector and magnitude.
$$
Magnitude (K) = A - B\\times D
$$
where A and B are constants defined based on our sensor max range.
D is the distance measured by the LiDAR.
* After calculating all necessary values we need to decide which sector is valid, we proceed to filter our magnitudes by applying a threshold. based on the research paper proposed by Ulrich and Bortenstien, which is an improved version of VFH called VFH+ they stated that due to the long time sampling of their ultrasound sensor and noise they proposed a solution by applying a hysteresis based filter where they set two threshold and any sector between these two thresholds depends on the state of the previous sector \[2]. in our case we will keep it simple right now by applying a simple threshold to filter our sectors. After filtering our sectors we end up with an array (vector) that holds the state of 32 sectors we have (true = open sector, false = closed sector) all the states are indexed.
* Angle enlargement: here it comes one of the most important steps that we need for our algorithm and it is angle enlargement, this angle will give our algorithm more privilege to  access our environment and build a better perception. This angle is calculated based on our robot dimensions and a safety margin that we choose. Based on the angle we calculated we proceeded to extend the angular region around the obstacle \[2]. all blocked sectors needs to be updated based on the number of sectors.
$$
\\alpha = asin(\\frac{r}{d})
$$r:  is the sum of robot radius plus safety margin if there is any.
d:  is the distance between the safety margin and the obstacle.
* Finally: We proceed to store valid pairs of sector indexes, which sets the start and end of an open sector.
